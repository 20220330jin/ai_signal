## 한국어 상세 요약 번역
카파시는 4월의 게시물을 다시 언급하며 LLM의 실제 능력에 대한 사람들의 이해 격차가 더 커지고 있다고 주장한다. 예전에는 서로 다른 두 집단이 대화가 통하지 않는 정도였으나, 지금은 경험과 접근 권한에 따라 가파른 깔때기처럼 분화되었다고 본다.

그는 대략 60억 명(75%)은 LLM을 거의 경험하지 못했고, 10억~20억 명(약 20%)은 무료 챗봇을 가끔 사용하며 검색이나 글쓰기 도구 정도로 생각한다고 추정한다. 반면 약 2,000만 명(0.2%)은 수학·코딩에서 최신 고성능 에이전트가 복잡한 프로젝트를 처리하는 모습을 경험하며, 약 5,000명(0.00006%)은 내부 최전선 시스템에 접근해 다수 에이전트가 장기간 협업하는 더 강한 역량을 경험한다고 설명한다. **이 수치는 공식 통계가 아니라 게시자의 거친 추정**이다.

그는 이러한 차이의 이유로 (1) 문제의 규모·난이도·장기성, (2) 디지털이고 결과 검증이 쉬우며 경제적 가치가 높은 영역에 집중되는 불균등한 능력, (3) 무료·유료·내부 시스템의 접근성 차이를 든다. 짧은 질문보다 장기적이고 어려운 문제에서 역량 차이가 두드러지며, 코드 테스트처럼 검증 가능한 보상이 강화학습에 유리하다는 설명이다.

대중은 여전히 어설픈 챗봇을 경험하고, 많은 전문직은 제한된 생산성 향상만 경험하지만, 일부 전문가는 능력 향상 속도에 압도된다. 이 경험들이 동시에 존재한다는 것이 글의 결론이다.

## 관련된 과거 게시물
스레드 아카이브에는 카파시가 다시 인용한 4월 게시물도 포함된다. 오래된 무료 모델 경험과 최신 Codex/Claude Code의 능력은 다르며, 특히 코드·수학처럼 검증 가능한 분야에서 차이가 크다는 논지를 보충한다.

## 용어
- Frontier model: 당시 최상위권 고성능 모델.
- Verifiable rewards: 자동 또는 명시적 기준으로 성공 여부를 판정할 수 있는 보상 신호.
- Jagged capabilities: 분야와 과제에 따라 능력 수준이 고르지 않은 현상.
- Agent swarm: 여러 에이전트가 역할을 나눠 작업하는 방식.

## 한국 개발자에게 의미
단순한 프롬프트 기술보다 크고 어려운 문제를 분해하고, 성공 기준을 명확히 만들며, 에이전트의 결과를 검증하는 능력이 중요할 수 있다. 테스트 통과만으로 요구사항 충족·안전성을 보장할 수는 없다.

## 권장 실험

## 학습 노트 — 왜 사람마다 AI의 능력을 다르게 느낄까?

### 1. Jagged capabilities: 들쭉날쭉한 능력
LLM의 능력은 하나의 숫자로 표현하기 어렵다. 어떤 모델은 복잡한 코드의 오류를 찾아내면서도 간단한 업무 지시의 숨은 조건을 놓칠 수 있다. **특정 벤치마크에서 좋은 점수**와 **내가 맡길 실제 업무를 안정적으로 처리하는 능력**은 다르다.

예를 들어 코드 작성은 테스트 실행으로 결과를 확인하기 쉽지만, 고객에게 적절한 사과문을 작성하는 일은 정답이 하나가 아니어서 평가 기준을 명확히 만들기 어렵다.

### 2. Verifiable rewards: 검증 가능한 보상
강화학습에서 모델이 낸 결과가 좋은지 나쁜지 비교적 명확하게 평가할 수 있는 신호를 말한다. 코딩 문제에서는 테스트 통과, 수학 문제에서는 답의 검산 등이 그 예다. 다만 테스트가 통과한다고 보안·유지보수성·사용자 의도까지 충족한 것은 아니다.

### 3. 에이전트와 챗봇의 차이
일반적인 챗봇은 질문에 답을 생성하는 데 초점을 둔다. 에이전트는 목표 달성을 위해 파일을 읽고, 도구를 호출하고, 실행 결과를 관찰하고, 다음 행동을 선택하는 반복 과정까지 수행할 수 있다.

예를 들어 “로그인 오류를 고쳐줘”라는 요청에 대해:
- 챗봇: 가능한 원인과 수정 코드 예시를 설명한다.
- 코딩 에이전트: 저장소를 탐색하고, 재현 테스트를 만들고, 코드를 수정하고, 테스트를 실행한다.

물론 도구 권한과 실제 실행 환경에 따라 수행 범위는 달라진다.

### 4. 체감 격차가 생기는 이유
**사용 경험**, **사용 가능한 모델·도구**, **문제의 난이도**, **결과를 검증할 능력**이 서로 다르기 때문이다. 따라서 “AI는 별로다”와 “AI가 복잡한 프로젝트를 수행한다”라는 관찰은 서로 다른 조건에서 동시에 나올 수 있다.

카파시가 제시한 인구 집단별 숫자는 정밀 조사 결과가 아닌 **개인적 추정**이다. 학습할 때는 논지와 숫자의 증거 수준을 분리해서 읽어야 한다.

### 실무 실험: 같은 과제를 세 방식으로 비교
작은 버그 하나를 골라 **직접 구현**, **AI 채팅 도움**, **코딩 에이전트 수행**을 비교해 보자.

| 측정 항목 | 왜 필요한가 |
|---|---|
| 작업 완료까지 걸린 시간 | 속도 비교 |
| 테스트 통과 여부 | 기능 검증 |
| 사람의 수정·승인 횟수 | 숨은 관리 비용 |
| 요구사항 누락 | 실제 품질 |
| 다음 날 코드를 설명할 수 있는가 | 개발자의 이해도 |

실험 결과를 기록하면 자신의 환경에서 AI가 실제로 유용한지 더 정확히 판단할 수 있다.
