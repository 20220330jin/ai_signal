## 학습 노트 — AI 안전과 보안의 차이

### 먼저 알아야 할 개념
**AI Safety(안전성)**는 모델이 의도하지 않은 행동을 하거나 위험한 결정을 내리는 문제를 다룬다. 예를 들어 에이전트가 사용자의 요청을 잘못 해석해 중요한 파일을 삭제하는 상황이다.

**AI Security(보안)**는 외부 공격자나 악의적인 입력이 시스템의 권한을 악용하는 문제를 다룬다. 예를 들어 에이전트가 웹페이지에서 읽은 악성 지시를 시스템 명령으로 오인하는 프롬프트 인젝션(prompt injection)이 있다.

두 개념은 겹친다. 파일 삭제라는 결과는 같아도, 모델의 실수 때문인지 공격자의 조작 때문인지에 따라 대응 방법이 달라진다.

### 실제 개발 예시: 코드 수정 에이전트
에이전트에게 버그 수정을 맡겼다고 가정하자.

1. 에이전트는 코드를 읽고 수정안을 제안한다.
2. 자동 테스트를 실행한다.
3. 테스트가 통과하더라도 실제 운영 DB 변경이나 배포는 별도의 승인을 요구한다.
4. 어떤 명령을 실행했고 무엇이 변경됐는지 로그를 남긴다.

이 설계에서 **최소 권한(least privilege)**은 에이전트가 필요 이상의 파일·계정·시스템에 접근하지 못하도록 하는 원칙이다. **승인 게이트(approval gate)**는 되돌리기 어렵거나 영향이 큰 작업에 사람의 명시적 판단을 요구하는 장치다. **감사 로그(audit log)**는 사고 이후 어떤 행동이 있었는지 확인할 수 있는 기록이다.

### 안전성 평가를 어떻게 해야 할까?
단순히 정답률만 보는 것은 부족하다. 정상 입력에서 성공하는지뿐 아니라 잘못된 입력, 모호한 요청, 악의적인 문서, 권한 부족 상황에서 어떻게 행동하는지도 평가해야 한다. 이를 **레드팀 테스트(red teaming)**나 적대적 평가라고 부른다.

| 점검 대상 | 실습 질문 |
|---|---|
| 권한 | 에이전트가 프로젝트 밖의 파일까지 읽을 수 있는가? |
| 승인 | 배포·삭제·결제 등 위험 작업 전에 멈추는가? |
| 복구 | 잘못 수정했을 때 원복 가능한가? |
| 기록 | 실행 명령과 수정 내역을 추적할 수 있는가? |

### 생각해 볼 질문
- 자동 테스트를 모두 통과한 코드라면 사람의 승인이 필요 없을까?
- AI의 실수와 외부 공격을 구분해야 하는 이유는 무엇일까?
- 안전한 시스템을 만들려면 모델 성능 개선과 권한 설계 중 어느 부분부터 시작해야 할까?

### 15분 실습
본인이 사용하는 코딩 에이전트의 권한을 조사해 보자. 파일 읽기·쓰기, 셸 명령 실행, Git push, 배포, 비밀정보 접근을 구분해 **자동 허용 / 승인 필요 / 금지**로 표시한다. 이 실습은 일반적인 AI 안전 설계 학습이며, 해당 X 게시물이 이런 구체적 구현을 지시했다는 의미는 아니다.
