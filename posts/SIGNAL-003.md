## 상세 한국어 내용 정리
카파시는 기존 RAG가 질의 시 원본 문서의 관련 부분을 매번 다시 찾아 조합하기 때문에, 이전 질의에서 발견한 복잡한 연결과 종합적 해석이 지속적으로 축적되지 않는다고 지적한다. 대안은 원본과 사용자 사이에 LLM이 작성·유지보수하는 상호 연결된 Markdown 위키를 두는 것이다.

새 자료가 들어오면 단순 색인하는 대신 기존 주제·인물 페이지를 갱신하고, 새로운 증거가 과거 주장과 충돌하는지 표시하며, 종합적 설명을 수정한다. 사용자는 자료 선정·질문·방향 결정을 담당하고 AI는 요약·연결·문서 관리 업무를 담당한다. 카파시는 에이전트와 Obsidian을 나란히 두고 실시간으로 결과를 탐색한다고 설명한다.

### 세 계층
1. Raw sources: 원본 자료. 불변이며 LLM은 읽기만 한다.
2. Wiki: LLM이 작성·갱신하는 개념·인물·비교·종합 Markdown 페이지.
3. Schema: AGENTS.md / CLAUDE.md 등으로 명시한 문서 구조·작업·검증 규칙.

### 세 작업
- Ingest: 새 자료를 읽고 사용자와 논의, 관련 위키·색인·로그를 갱신. 하나의 자료가 10~15개 문서에 영향을 줄 수 있다.
- Query: 위키를 검색하고 근거를 들어 답하며 가치 있는 답변 자체를 다시 위키에 저장한다.
- Lint: 문서 간 모순, 오래된 주장, 고립 문서, 누락된 연결·개념·근거를 점검한다.

### 탐색과 도구
index.md는 내용별 목록, log.md는 시간순 변경 기록이다. 적당한 규모에서는 색인만으로도 탐색 가능하며, 규모가 커지면 qmd 같은 검색 도구를 고려한다. Obsidian은 Markdown 편집·링크·그래프 탐색 UI이며, Git으로 버전 관리한다. Web Clipper, Dataview, Marp 등은 선택 사항이다.

### 철학
유지보수 부담 때문에 사람의 위키가 방치되기 쉬운데, LLM이 반복적인 문서 관리 작업을 맡으면 지식이 지속적으로 축적될 수 있다는 제안이다. Vannevar Bush의 Memex 구상과 연결한다.

## 주장과 검증
- 확인: 위 설계는 카파시의 Gist에 실제로 기술되어 있다.
- 주장/경험: 위키가 누적적으로 풍부해지고 관리 부담이 크게 줄어든다.
- 미검증: 모든 RAG 방식보다 더 정확하거나 저렴하다는 일반적 성능 우위. LLM이 자동으로 모순을 놓치지 않는다는 보장도 없다.
- AI SIGNAL 해석: 원본·위키·규칙을 분리하고 출처/수정 기록을 유지하는 것이 지식의 신뢰성에 중요하다.

## 학습 노트 — RAG에서 누적형 지식 관리까지

### 1. RAG를 먼저 이해하자
**RAG(Retrieval-Augmented Generation)**는 답변할 때 외부 자료를 검색해 모델의 입력에 포함시키는 방식이다. 예를 들어 사내 문서에서 관련 문단을 검색하고, 그 문단을 바탕으로 질문에 답하게 할 수 있다.

RAG는 유용하지만, **검색한 내용을 이해하고 연결한 결과를 다음에도 사용할 수 있게 보존하는지**는 별도의 설계 문제다. 모든 RAG가 과거 분석을 버리는 것은 아니다. 카파시가 강조하는 것은 검색 자체의 폐지가 아니라 **지속적으로 갱신되는 지식 계층**이다.

### 2. Raw / Wiki / Schema를 구분하는 이유
- **Raw**: 출처와 작성 시점을 가진 원본 기록. 임의로 고치지 않는다.
- **Wiki**: 원본들을 비교해 만든 현재의 설명. 새로운 증거가 나오면 갱신한다.
- **Schema**: AI가 자료를 어떻게 읽고 기록·수정·검증할지 정의한 운영 규칙.

예를 들어 어떤 연구자가 4월에 “에이전트는 장기 작업에 약하다”고 주장했고, 10월에 새로운 실험이 나왔다면 과거 원문은 그대로 보존한다. 위키에서는 두 시점의 근거를 비교하고, 현재의 판단과 불확실성을 새로 정리한다.

### 3. Ingest / Query / Lint는 무엇인가?
**Ingest(편입)**: 자료를 읽고 기존 문서와 비교하여 새 지식을 반영한다.

**Query(탐구)**: 축적된 자료를 대상으로 질문하고, 중요한 종합 분석을 다시 지식으로 남긴다.

**Lint(정합성 점검)**: 링크 오류, 서로 모순되는 설명, 오래된 주장, 출처가 없는 결론을 찾아낸다.

이 세 과정이 함께 있어야 단순한 요약 파일 모음이 아닌 **지속적으로 관리되는 지식 저장소**가 된다.

### 4. Markdown, Git, Obsidian의 역할
**Markdown**은 사람이 읽을 수 있는 텍스트 문서 형식이다. **Git**은 누가 어떤 내용을 언제 바꿨는지 기록하는 버전 관리 도구다. **Obsidian**은 Markdown 문서를 링크와 그래프로 탐색하는 편집 도구다. 세 도구는 서로 대체 관계가 아니라 역할이 다르다.

### AI SIGNAL에 적용하는 작은 실습
1. 기존 게시물 두 개에서 같은 주장을 다루는 부분을 찾는다.
2. 두 주장에 공통으로 적용되는 질문을 하나 작성한다.
3. **확인된 사실 / 작성자의 주장 / 내 해석 / 아직 모르는 것**으로 구분한다.
4. 주제 문서에 현재 판단을 적고, 근거가 되는 SIGNAL 문서를 연결한다.
5. 새로운 글이 들어왔을 때 이 판단을 다시 검토한다.
